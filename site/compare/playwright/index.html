SessionForge vs Playwright

They do different jobs: SessionForge is for exploratory, logged-in, multi-role work by you and your coding agent; Playwright is for repeatable regression suites in CI across browsers.

What you needSessionForgePlaywright
Walk cases once with real loginsYes, log in once per session and keep itPossible, with scripted logins or saved storageState files
Watch several roles side by sideYes, up to four panes in one windowNo, it is a test runner, not a browser you look at
Coding agent drives your logged-in sessionsYes, through the built-in MCP serverNot its job
Repeatable suites on every change, in CINo, SessionForge does not run tests in CIYes
Chromium, Firefox and WebKitChromium onlyYes
Traces and exact pass/fail resultsNo; an agent can take screenshots and read logsYes

Using both today

  1. Log in once per role in SessionForge and explore the feature yourself, or let your agent walk the cases.
  2. When a case should hold on every change, write it as a Playwright spec and run it in CI.
  3. Use SessionForge again when a spec fails and you want to see the problem as each role.

SessionForge's own end-to-end tests are written with Playwright.

Export to Playwright Planned

These are on the roadmap under Later (evaluating). They are not in any release yet, and the roadmap is a plan, not a promise.

  • Export a session as a Playwright storageState file, so a spec starts logged in as that role.
  • Turn what you or your agent did in a pane into a Playwright spec.
  • Playwright codegen launched inside a logged-in session.

About storageState files. They contain live cookies and tokens. Add them to .gitignore and never export production logins.
