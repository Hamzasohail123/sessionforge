Security model

Agents act with a session's real cookies, so what an agent does is done as that logged-in user. These limits apply whatever your editor allows.

  • Off by default. Nothing listens until you turn it on.
  • 127.0.0.1 only. Only 127.0.0.1/localhost Host headers are accepted, and every request with an Origin header is refused, so web pages can't reach it.
  • Bearer token. 256-bit, stored encrypted with the OS keyring. Rotate it in the panel; old clients get 401.
  • Per-session access: Hidden, Read or Control. New sessions start at Read. Hidden sessions are not listed and can't be addressed.
  • Production is read-only unless you type the session name to confirm; that lasts until SessionForge restarts.
  • URL guards apply to agent navigation, requests, redirects and popups. Agents can never call SessionForge's own import or MCP server.
  • Stop. A "🤖 Agent" label and a Stop button appear in the pane an agent uses; Stop sets the session back to Read and ends the running call. The activity log lists every call.
  • Redaction. Cookie, Set-Cookie, Authorization and other secret headers, query parameters and JSON keys are redacted; page content is labelled untrusted; calls are rate limited. There is no eval, CDP, file or shell tool.

Known limits. Read access allows GET, HEAD and OPTIONS through send_request_as, and a GET can still have side effects (for example /logout). Local malware with your user's rights can read session data. See SECURITY.md.
